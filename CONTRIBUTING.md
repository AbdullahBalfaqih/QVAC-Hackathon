# Contributing

Contributions that improve accessibility, evidence handling, local inference or reproducibility are welcome.

1. Open an issue describing the problem and the proposed scope before a large change.
2. Do not include private worker records, credentials, model weights, `node_modules` or unconsented personal data in commits or screenshots.
3. Preserve the human-review boundary: literal matching must not be presented as source verification or legal judgment.
4. Run `npm test` on Node.js 22.17 or later. If changing the UI or local inference, describe the platform, model, commands and observed results; do not claim untested platforms.
5. Keep source and asset provenance, licensing and disclosure documentation current. Distinguish generated assets and illustrative media from live test results.

Security and privacy concerns are described in [SECURITY.md](SECURITY.md). Do not publish sensitive examples in a public issue.
